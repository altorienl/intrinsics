## MSFT debt-to-equity root cause

ROOT CAUSE: /Users/alockwood/intrinsics/index.html line 1988 builds the "Total debt" figure as `(bs.longTermDebt || 0) + (bs.shortTermDebt || 0)`, which omits `capitalLeaseObligations`. FMP's `debtToEquityRatioTTM` numerator is `bs.totalDebt`, and `totalDebt == shortTermDebt + longTermDebt + capitalLeaseObligations` exactly. For MSFT at 2026-09-30: FMP totalDebt 133,931,000,000 / equity 470,509,000,000 = 0.2846513031631701, bit-for-bit identical to the published debtToEquityRatioTTM. The app prints that ratio next to 35,481,000,000 (ST 4,391 + LT 31,090), so the $98.45B of lease obligations is the entire discrepancy. Implied debt from the ratio minus displayed debt = 98.450B = capitalLeaseObligations to the dollar.

PERIOD IS NOT A FACTOR. Despite the "TTM" suffix, the balance-sheet ratios in /fmp/ratios-ttm are point-in-time, computed off the same latest quarter the app fetches with `period=quarter&limit=1`. Verified by exact float equality across 19 tickers spanning seven distinct fiscal quarter-ends (AAPL 2026-06-27, NVDA 2026-07-26, WMT 2026-07-31, HD 2026-08-02, COST 2026-08-30, ORCL 2026-08-31, KO 2026-10-02 among them). The app's printed period label "Q1 2027" is correct.

SYSTEMATIC, NOT A MSFT QUIRK. 12 of 19 sampled tickers are wrong, and the error equals the lease share: MSFT -73.5%, TSLA -43.6%, SBUX -40.8%, AMZN -36.3%, WMT -31.7%, DAL -29.1%, COST -28.1%, META -27.8%, NVDA -14.1%, HD -13.0%, GOOGL -11.8%, T -10.4%. It reads correct only where capitalLeaseObligations is zero (AAPL, KO, JPM, PFE, XOM, UNH, ORCL), which is why it went unnoticed.

AUTHORITATIVE FIX: change the SUPPORTING FIGURES, not the ratio and not the labels. Source the numerator from `bs.totalDebt`, which is already in the response the app already fetches and is currently referenced zero times in index.html. The ratio must not move: it is what the sector benchmarks grade against in both index.html (g(), line 2094) and the offline screener (.github/scripts/scan.py line 103, which reads debtToEquityRatioTTM straight into grades.json), so changing it would desync the live card from the precomputed screener and from benchmarks calibrated on lease-inclusive leverage. It would also break coherence with debtToAssetsRatioTTM, debtToCapitalRatioTTM and financialLeverageRatioTTM, all verified to use the same totalDebt numerator. No label change is needed: $133.9B genuinely is total debt post-ASC 842, whereas the current $35.5B is borrowings mislabeled as total debt. Excluding leases would understate leverage precisely for the lease-financed companies where leverage matters most. Nothing was modified, committed, or deployed.

### Debt-to-equity components omit lease obligations, contradicting the ratio printed beside them — HIGH

**Evidence.** /Users/alockwood/intrinsics/index.html:1988 — `var debtVal = (bs.longTermDebt || 0) + (bs.shortTermDebt || 0);` feeds the components string at lines 1998 and 2008 (`'Total Debt: ' + cs + fmt(debtVal) + ' / Equity: ' + cs + fmt(equity)`), while the value displayed at line 1997 is `rt.debtToEquityRatioTTM`. Verified live: MSFT balance sheet 2026-09-30 has shortTermDebt 4,391,000,000, longTermDebt 31,090,000,000, capitalLeaseObligations 98,450,000,000, totalDebt 133,931,000,000, totalStockholdersEquity 470,509,000,000. 133931/470509 = 0.2846513031631701, identical to the published debtToEquityRatioTTM. The app shows that ratio alongside 35,481,000,000, understating the numerator by exactly the 98,450,000,000 of leases. Both identities (totalDebt == ST + LT + capitalLeaseObligations, and debtToEquityRatioTTM == totalDebt/totalStockholdersEquity) held for all 19 tickers tested. `bs.totalDebt` is fetched but referenced 0 times in index.html.

**Fix.** Replace line 1988 with a totalDebt-sourced value, defensively falling back to the component sum: `var debtVal = (typeof bs.totalDebt === 'number') ? bs.totalDebt : ((bs.longTermDebt || 0) + (bs.shortTermDebt || 0) + (bs.capitalLeaseObligations || 0));`. This is the single authoritative fix. Do not touch the ratio value, the formula label "Total Debt / Shareholders' Equity", or the period label; all three are already correct once the figure matches FMP's definition. Optional polish only: append the lease split, e.g. "incl. $98.5B leases", since a reader tying to the 10-Q cover will otherwise go looking for $35.5B.

### Fallback branch silently switches the debt definition when FMP omits the ratio — MEDIUM

**Evidence.** /Users/alockwood/intrinsics/index.html:2001-2010. When `rt.debtToEquityRatioTTM` is absent or zero, the app computes `debtVal / equity` from the lease-excluding `debtVal`, then grades that number against the same sector benchmarks (g(), line 2094) that were calibrated on FMP's lease-inclusive ratio. For MSFT the two definitions differ by 3.8x (0.2847 vs 0.0754). The same ticker can be graded on two different definitions of leverage depending only on whether one endpoint returned a value, and the lease-excluding path is systematically the more flattering one.

**Fix.** Fixing line 1988 resolves this automatically, since both branches read the same `debtVal`. Worth confirming after the change that the fallback result is definitionally identical to the API path rather than merely closer to it.

### Negative-equity leverage grading diverges between the live app and the offline screener — LOW

**Evidence.** /Users/alockwood/intrinsics/index.html:1992-1996 stores `Math.abs(deApi)` as the value, and the grader at lines 2100-2104 then compares that absolute value against lower-is-better benchmarks. The offline screener at /Users/alockwood/intrinsics/.github/scripts/scan.py:123 instead hard-codes `'bad' if (de is not None and de < 0)`. A company with small negative equity, say D/E of -0.30, grades 'good' in the live app (0.30 <= 0.50 Technology benchmark) but 'bad' in grades.json. SBUX is live-confirmed negative at -2.9226, where the two paths agree only because the magnitude clears the 'bad' threshold anyway. The components string is replaced by an explanatory sentence in this branch, so this is a grading inconsistency rather than a figure inconsistency.

**Fix.** Make index.html match scan.py by grading negative debtToEquity as 'bad' unconditionally rather than grading the absolute value. Out of scope for the reported defect; flagged because it is the same class of problem, two code paths disagreeing on one metric's definition.

### Reporting-period mismatch ruled out as a contributing cause — INFO

**Evidence.** The hypothesis that TTM ratios and the quarterly balance sheet carry different dates does not hold. /Users/alockwood/intrinsics/index.html:1886 fetches `period=quarter&limit=1` and line 1889 fetches `ratios-ttm`; for MSFT both resolve to 2026-09-30 (Q1 FY2027). Exact float equality of totalDebt/equity against debtToEquityRatioTTM across 19 tickers with seven different fiscal quarter-ends proves FMP computes the balance-sheet ratios from that same latest statement. The "TTM" suffix is a blanket naming convention on the ratios-ttm payload, applied even to pure point-in-time balance-sheet ratios. Separately verified that currentRatio, assetTurnover, operatingMargin, grossMargin and netMargin all reconcile exactly between the app's locally derived components and FMP's published values, isolating the defect to debt-to-equity alone.

**Fix.** No change needed. One residual risk for the owner: balance-sheet-statement and ratios-ttm are separate upstream caches, so if FMP publishes a new quarter to one before the other, the figure and the ratio can briefly disagree even after the fix. If that transient matters, compare the balance sheet date against a date field on the ratios payload before trusting the pairing.
